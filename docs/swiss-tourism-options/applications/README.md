## 各字段的写法

| 字段 | 本稿组织方式 | 仍需补齐 |
| --- | --- | --- |
| Describe | 用户、用途、技术工作方式；不含个人联系人或敏感规则 | 正式名称、最终范围 |
| Innovation | 问题 → 核心机制 → 与替代方式的区别 → 如何建立优势 | 访谈、竞品比较、可验证差异 |
| Technology & Product | 明确设计阶段与 TREK 来源；首版、六周、中期、风险 | 实际开工与进度、数据访问结果 |
| Team | 已提供的真实经历 → 个人责任 → 所需协作与建队 | 具体时间投入、真实合作承诺 |
| Market | 客户与买方 → 可服务市场 → 替代方式 → 验证计划 | 方括号客户数量、实际验证 |
| Sustainability & Impact | SDG 关联 → 受益者 → 反事实与 KPI → 未有结果 → 负面影响 | 真实基线、规模目标与测量数据 |
| Business | 定价假设、获客、成本、里程碑、风险 | 融资、月度成本、实际价格与合同 |

Team 的成果来自创始人简历；涉及公开可核实的个人成果，提交前准备项目、履历和奖项证明。除已有简历外，本稿未独立审计这些成果。

## Market 怎么补

当前唯一加入的行业数字是 FSO 的 2025 酒店统计背景：43.9 million hotel nights、4,456 hotels surveyed。住宿夜数不是独立游客人数，调查酒店数量不是可采购客户数，也不覆盖所有家庭、居民、户外用户或企业。

市场框架需按方向填：

- 个人产品：目标地区符合条件的人或旅程数 × 可验证购买频率 × 测试客单价。
- 酒店产品：明确地区、规模和需求条件的酒店数量 × 可验证年合同额。
- 机构产品：可采购的旅行社、会议客户或目的地机构数量 × 真实采购频率与年合同额。
- 多人产品：组织者或公司数量；不要按组内成员数量计算买方。

若申请前仍没有验证，只能如实给出有依据的估算和假设，不写已证实需求。收入预测、市场容量和六周试点目标分别记录。

## Spotlight 选择

官方 2027 主题是 Work, Reimagined，关注人、团队和行业如何准备未来工作，包括 AI 带来的任务变化、学习、领导力及关键行业等。2026 的 Apertus 主题不应套用到 2027。[官方说明](https://www.venture.ch/copy-of-spotlight-award-1)

以下为产品分析，不是主办方资格承诺：

| 方向 | 建议 | 必须成立的事实 |
| --- | --- | --- |
| 01 周末短途 | 游客／居民版 No | 雇主版若选 Yes，需要真实员工支持问题与流程 |
| 02 动态行程 | 游客版 No；工作人员版可评估 | 旅行服务人员的调整劳动是核心 |
| 03 票券 | 游客版 No；旅行社版可评估 | 真实报价审核工作及技能支持 |
| 04 亲子 | 家庭版 No | 酒店／机构员工版需要独立工作证据 |
| 05 多代同行 | 家庭版 No | 不能把家庭组织活动自动等同工作创新 |
| 06 酒店礼宾 | 有较强 Yes 叙事基础 | 员工辅助、可复用知识、核验与增能是产品核心 |
| 07 商务短游 | 倾向 No | 商务旅行本身不等于改变工作方式 |
| 08 无车户外 | 用户版 No | 机构分发渠道本身不足以证明工作主题 |
| 09 目的地分流 | 条件性 Yes | 运营协作、工作人员决策与小商家支持是核心 |
| 10 多人协调 | 朋友版 No；企业版可评估 | 确实改善企业组织者劳动与协作 |

对于酒店方案，强叙述应是“让前台团队维护、学习和复用可靠知识，把重复查询转为有监督的个性化服务”。需要测咨询工时、核验工作量、培训与员工接受度，同时讨论岗位替代、去技能化和新增负担；不能只说 AI 节省时间。

## Video Introduction

用户提供限制为可选、最多 5 分钟、250 MB。建议 90–150 秒，先明确自己、用户与问题，再展示核心机制、真实阶段和下一步。

每个方向已给独立演示情境。只有设计原型时明确标为 prototype/concept；历史项目可证明个人能力，但不能充当本旅游产品。模拟天气或交通样本与真实数据分开说明。

建议英文开场：

> I'm Leo Zhong, a solo founder based in Zurich. My background is in production AI and live software services. I'm now exploring [selected tourism problem]. This concept is at design stage, and I will validate it with [target users] before expanding the product.

后续录制前应替换方括号，不拍入真实游客数据或凭证。

## 修改与复核

机器可读正文保存在 [drafts.json](drafts.json)，对应十份 Markdown 提供可复制段落。校验脚本检查字符范围、显示字符数与 JSON 一致性、本地链接，以及待补充占位符。

在仓库根目录运行：

```bash
python3 docs/swiss-tourism-options/applications/validate_drafts.py
```

如果修改 Markdown，也同步修改 JSON；运行脚本会发现不一致。替换占位符后再次计数，尤其不要把标题、来源或额外句子直接拼入字段而不核验。
